## 关键决策与理由

| 决策 | 备选 | 为什么 |
| --- | --- | --- |
| 在 `SessionOutputCoalescer` 最前面截流，网关在输出层 | 在 SSH 层解析 | 四种会话（ssh/local/serial/telnet）共用一条路径，不用各改一遍 |
| 布局叶子数字 = pane **id** 数字（`%12`→12） | `#{pane_index}` | 实测：window `@1` 的 pane_index=0 而 layout 里写 `1`；用 index 会全黑 |
| capture 拆成三条独立命令 | 一条 `;` 串联 | tmux 3.2 对含 `capture-pane` 的串联行回 `%error parse error: syntax error` |
| 命令应答用 `NYATERM-REPLY:` 标签配对 | 按 `%begin` 块顺序配对 | 初始化、capture、用户命令行可能同时在飞 |
| 网关内按 pane 流式解码 | 先转 UTF-8 再交给前端 | GBK 会话中文会全变 U+FFFD；拆包的多字节字符必须是流式解码 |
| 前端只信后端快照，不做乐观更新 | 前端先改再等确认 | 和 tmux 真实状态打架时会出现"点了没反应/点两次" |
| capture 顺序竞争不修 | 丢回放 / 缓存重放 | 客户端没有正确解（丢回放丢整屏，缓存重放重复），只能 tmux 侧加序列号；写进已知限制 |
| 前缀键前端模拟 | 指望 tmux 的 prefix | 控制模式下 tmux 不渲染自己的状态栏，prefix 对用户不可见 |
| 用 fork + 保留原作者 | 新建独立仓库 | 用户选的是 fork；且历史提交不该被改写 |
| Windows 用 portable.flag | 常规安装包 | 用户要"解压就能跑"，且 portable 有独立标识与 data 目录，不受已安装版本的单实例劫持 |
